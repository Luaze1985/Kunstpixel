Helt enkelt forklart: API vs. MCP

Glem kode, servere og JSON et øyeblikk.
Tenk på Kunstpixel som et fysisk museum med en datamaskin bak i resepsjonen.

Tradisjonelt API
🔌 Som en stikkontakt i veggen

En stikkontakt gir strøm, men den snakker ikke med deg.

  • For at noe skal fungere, må et menneske (en elektriker/programmerer) på forhånd ha koblet riktig ledning med riktig plugg inn i kontakten.
  • Hvis du spør en KI om å bruke en stikkontakt uten ledning, vet den ikke hvor kontakten er, hvor mange volt den har, eller hva som skjer hvis den plugger i feil ting.

I praksis: Et API er bygget for programmerere som vet nøyaktig hvilken adresse de skal gå til.

MCP (Model Context Protocol)
🛠️ Som en verktøykasse med bruksanvisning

Tenk deg at du gir KI-en en verktøykasse der hvert verktøy har en stor merkelapp:

  • 🏷️ Verktøy 1: "Søk etter bilde" — Bruk dette når publikum spør hvor et bilde henger.
  • 🏷️ Verktøy 2: "Sjekk åpningstid" — Bruk dette for å finne ut når dørene åpner.

KI-en ser verktøykassen selv. Når en gjest spør: "Hvor er Skrik?", skjønner KI-en automatisk:
👉 "Aha! Da må jeg plukke opp Verktøy 1, slå opp 'Skrik', og så fortelle svaret til gjesten."

I praksis: MCP gjør at KI-en kan bruke fagsystemet ditt uten at du må kode hver minste samtale på forhånd.

Kort oppsummert: Hva skal du si til andre?

"Et API er for dataprogrammer som snakker med dataprogrammer.
MCP er for at KI-agenter skal få hender og verktøy til å gjøre oppgaver for oss trygt."

De 3 tingene du trenger å huske:

  1. API: Krever en programmerer som bygger broen hver eneste gang.
  2. MCP: KI-en forstår selv når og hvordan den skal bruke verktøyet.
  3. Trygghet: Med MCP kan vi gi KI-en lov til å lese samlingen, men vi låser døra så den aldri kan slette eller endre noe.
